# IRLIX Services — правила работы агента

Цель — надёжно решать задачи проекта: выбирать необходимые действия по цели, неопределённости и последствиям, критически проверять решения и доводить согласованную работу до подтверждённого результата.

## Обязательный минимум

- Определи цель, границы и конечную точку запроса. Исследование, реализация и production-релиз имеют разные результаты. Не подменяй цель предложенным способом.
- Проверь необходимые актуальные источники. Не выдумывай бизнес-правила, доступы, выполненные действия и проверки. Различай факт, гипотезу, предложение и принятое решение.
- После первичного анализа и до реализации кратко сообщи владельцу, как понял цель и результат, что собираешься сделать и как проверишь итог. Для исследования назови подход и ожидаемый результат анализа. Соразмеряй подробность с задачей; это сообщение не требует нового согласования уже разрешённой работы. Существенные неизвестные решения обсуди до зависимых изменений по [workflow](docs/agent/WORKFLOW.md).
- Самостоятельно выполняй обратимые технические шаги внутри согласованного объёма. Существенные бизнес-неоднозначности, изменение архитектурного подхода, потери данных и выход за полномочия требуют решения владельца после исследования вариантов. Уже данное разрешение не запрашивай повторно без изменения его границ.
- Сохраняй чужую работу и данные. Репозиторий публичный: секреты, реальные персональные/коммерческие данные и приватные ТЗ не публикуются. Непроведённые проверки — `NOT TESTED`, не `PASS`.
- Запрос ведётся до результата: PR, ожидание CI, сообщение о статусе и ответ помощника не являются завершением. Исправляй ошибки и продолжай. При настоящем блокере сохрани состояние и укажи нужное действие; не обещай несуществующую фоновую работу. Команда владельца остановиться действует немедленно.

## Выбор действий

Начни с [единого workflow](docs/agent/WORKFLOW.md). Выбирай совместимые [поведенческие модули](docs/agent/BEHAVIORS.md) по обнаруженным фактам и переоценивай выбор при новых данных. Компетенция означает действия и evidence; она не требует отдельной роли или subagent автоматически. Не загружай все модули заранее.

Проектные знания ищи адресно по [границам контекста](docs/CONTEXT_SCOPE.md) и [маршрутам](docs/context/MANIFEST.json). Технические инварианты — [горизонтали](docs/policies/ENGINEERING.md); продуктовые требования — приватный `ideas/company-internal-services-81-2.4/`. Shared UI — `@irlix/ui`; владение данными за сервисом, чужие таблицы недоступны напрямую, интеграции через API/события. Структурные изменения требуют актуализации [карты сервисов](docs/SERVICE_MAP.md).

- **Laravel backend — обязательная архитектура для нового/изменяемого сценария:** `route → Controller (HTTP) → Application/Service (use case, транзакция) → Eloquent Model (свои данные)`; проверки permission + scope на сервере, явно контролируемая сериализация API. Не размещать бизнес-логику/`DB::table()` в маршрутах, контроллерах и обычных сервисах. Исключения и legacy-переход — строго по [Backend](docs/horizontal/BACKEND.md#архитектура-laravel--обязательный-контракт) и [Database](docs/horizontal/DATABASE.md). **Не переносить это правило механически на FastAPI и другие стеки.**

## Завершение и полномочия

- Изменения — в отдельной ветке от свежей `development`, завершённый объём — PR в `development`, проверки точного SHA до/после интеграции. Не перетирать параллельные изменения и не force-push общую историю. [Git](docs/BRANCHING.md).
- Production — только по прямой команде владельца, накопительным проверенным fast-forward `development → main`; дождаться фактических deploy/smoke. [Релиз](docs/policies/GIT_RELEASE.md).
- Один ведущий отвечает за весь результат. Помощники — по независимости/параллелизму и реальным возможностям среды; [делегирование](docs/agent/DELEGATION.md). Кастомные Skills остаются отключены: [статус](docs/AGENT_SKILLS.md).
- Незавершённая задача — [состояние и возобновление](docs/agent/STATE.md). Подтверждённые повторные проблемы — [Kaizen](docs/CONTINUOUS_IMPROVEMENT.md), без самовольного изменения процесса.
- Итог — [REPORTING](docs/REPORTING.md). Правила среды и явные инструкции владельца учитываются по их действительному приоритету; локальный файл не создаёт отсутствующих полномочий или инструментов.
