# IRLIX Services

Монорепозиторий платформы внутренних сервисов IRLIX.

## Первый этап

Первый этап разработки включает:

1. инфраструктурный каркас;
2. Platform Core;
3. общий frontend shell;
4. первый эталонный бизнес-сервис `Employees`;
5. после стабилизации шаблона — `Vacations`.

## Структура

```text
apps/
  web/                  # общая Vue 3 SPA / platform shell
services/
  platform-core/        # общесистемный backend
  employees/            # сервис сотрудников и оргструктуры
infra/
  postgres/             # инициализация общей PostgreSQL
```

Бизнес-сервисы изолированы по доменным границам. Прямой доступ одного сервиса к таблицам другого запрещён.

На первом этапе используется одна физическая PostgreSQL с отдельными схемами по владельцам данных. Это временная инфраструктурная оптимизация, а не объединение доменов: сервис должен иметь возможность позднее переехать в отдельную БД без переписывания предметной логики.

## Локальная инфраструктура

Требуется Docker с поддержкой Compose.

```bash
cp .env.example .env
docker compose up -d postgres redis rabbitmq
```

Сервисы приложения будут добавляться в Compose по мере реализации.

### PostgreSQL

Одна база `irlix_services`, стартовые схемы:

- `platform_core` — данные платформенного ядра;
- `employees` — данные Employees.

Каждый backend в приложении должен работать только со своей схемой/своими таблицами.

### RabbitMQ

Management UI локально доступен на `http://localhost:15672`.

### Redis

Используется как инфраструктурный компонент для cache/queue/locks там, где это требуется конкретному сервису.

## Принципы

- один репозиторий, отдельные каталоги сервисов;
- общий frontend shell;
- независимые backend-сервисы;
- REST для синхронного взаимодействия;
- RabbitMQ для доменных событий и асинхронных процессов;
- versioned events, idempotency, retry и dead-letter обработка;
- отсутствие прямого межсервисного доступа к таблицам;
- отдельный жизненный цикл каждого сервиса сохраняется даже внутри монорепозитория.
