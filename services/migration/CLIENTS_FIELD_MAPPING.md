# Clients: соответствие полей исторического переноса

Схема старого Clients сверена по предоставленному оператором SQL 12.10.2026. Это описание адаптера после перехода на ClientMember (PR #571), а не подтверждение production переноса. Строк источника в Git нет; необходим новый Inspect и Dry run.

| Legacy | Новая сущность и правило |
|---|---|
| members.id | Mapping clients/members. Повторные строки одного человека у клиента ссылаются на один client_members через alias_of; числовой ID не копируется. |
| members.memberable_type, memberable_id | employee разрешается через users/Employees, subcontract через subcontracts/partner_specialists. Иной тип блокируется. |
| members.client_id, project_id | Клиент проекта сверяется с client_id. Старая проектная связь сохраняется в предупреждении, но без дат не создаёт project_assignments. Основной проект автоматически не создаётся. |
| members.attached_by | Автор добавления сохраняется в приватных metadata. |
| rates.id, member_id | Mapping clients/rates на member_terms.client_member_id, project_member_id остаётся NULL. |
| rates.start_date, end_date | valid_from и valid_to; открытое окончание остаётся NULL. |
| rates.workload | hours_per_day, проверка диапазона 0–24 и точности до сотых. |
| rates.technology_id, grade | Название технологии и level; отсутствующее значение остаётся NULL с предупреждением, неизвестная ссылка блокирует строку. |
| rates.rate | При clients_defer_rate_amounts=true новая сумма остаётся NULL, существующая сохраняется. Иначе требуется проверенное число либо расшифровка. |
| rates.is_revision, reason | Приватные metadata без выдуманного события пересмотра. |
| created_at, updated_at | Исходные даты при создании; дата создания существующей строки не переписывается. |

Имя сотрудника составляется из фамилии, имени и отчества. Партнёрская личность остаётся отдельной от Employee. Связь с попыткой подключения из имён или дат не выводится.

Перекрывающиеся интервалы одного ClientMember с одинаковыми записанными коммерческими полями объединяются; все исходные rate ID получают mapping на каноническое условие. Отличающиеся перекрытия требуют ручной сверки. Изменение сопоставленного условия в защищённом отчётном периоде блокируется. Старые mappings на project_members, прежние member_terms и default_projects требуют отдельного согласования.

Обычные бизнес API требуют ставку, технологию и грейд. Исторический импорт допускает NULL. В ДДС и отчётных периодах неизвестная сумма отображается как «—», часы сохраняются, а реальный ноль остаётся числом 0.

Конвертированный лид с подтверждённым client_id переносится успешным с предупреждением об ином исходном статусе. Старые client_requests из предоставленной схемы имеют обязательную client_id и не имеют lead_id: связь не выдумывается. Если источник явно содержит lead_id, пара сверяется с converted_client_id; повторный импорт не удаляет сохранённую ссылку. Новые назначения аккаунтов, замещения и история привлечения не выводятся из старых полей. Feedback/content/date/rating/interview_id пока остаются в metadata.

Проверки: client_member_import_smoke.php покрывает идентичности, повторные подключения и ставки, Dry run, Timesheets и Validate; vacations_schema_import_smoke.php сохраняет отдельную проверку Vacations. Старый schema_import_smoke.php — архивный fixture прежней модели. unknown_rates_smoke.php проверяет неизвестную, нулевую и числовую ставку в отчётах.

Обновление кода не запускает production перенос. Нужны проверка обновления PostgreSQL схемы, инвентаризация реальных строк, сверка частичных mappings и контроль часов/сумм после импорта. Подробности: docs/MIGRATION.md.
