# Specialists

Backend сервиса профессиональных профилей специалистов.

## Ответственность

- хранит грейд, технологии и компетенции специалиста;
- хранит профессиональный профиль уволенного сотрудника;
- является source of truth каталога технологий и компетенций;
- получает сотрудника, кадровый статус и оргструктуру только через Employees API;
- не читает схему Employees напрямую;
- проверяет область доступа руководителя на backend для каждого профиля.

## MVP API

- `GET /api/health` — healthcheck;
- `GET /api/workspace` — scoped список специалистов, подразделений и каталог компетенций;
- `GET /api/people/{employee}` — карточка специалиста в доступной области;
- `PUT /api/people/{employee}` — изменение профессионального профиля;
- `GET /api/catalog` — технологии и компетенции;
- чтение каталога доступно любому авторизованному пользователю платформы, чтобы селекты технологий в других сервисах работали независимо от его роли; изменение каталога по-прежнему ограничено правами Specialists;
- `POST /api/catalog/technologies` — добавить технологию;
- `PUT /api/catalog/technologies/{technology}` — изменить технологию;
- `DELETE /api/catalog/technologies/{technology}` — удалить технологию.

Employees предоставляет внутренний контракт `GET /api/specialists-directory`. Для обычного пользователя он доступен только руководителю подразделения и возвращает его department tree; `platform-admin` получает полный scope. Уволенные не фильтруются.

На текущем этапе любой пользователь, имеющий доступ к Specialists, может управлять корпоративным каталогом технологий. Если позже потребуется выделить отдельных владельцев каталога, это оформляется отдельным permission без изменения модели данных.

## Данные

Собственная PostgreSQL schema: `specialists`.

Таблицы первой версии:

- `specialist_profiles`;
- `technologies`;
- `competencies`;
- `specialist_technologies`;
- `specialist_competencies`.

`last_department_id` сохраняет последнюю известную организационную принадлежность вместе с профессиональным профилем.

### Каталог технологий

Начальный каталог технологий засеивается миграцией `2026_09_27_000002_seed_technologies.php` по данным из предыдущей реализации.

Поля каталога:

- `name` — отображаемое название технологии;
- `alias` — короткое название из предыдущей реализации; пока сохраняется как справочное и не участвует в бизнес-логике;
- `category` — прежняя привязка к направлению (`Backend`, `Frontend`, `Mobile`, `QA`, `Analytics` и т. п.); пока сохраняется как справочная и не используется для разграничения доступа;
- `parent_id` — иерархия технологии/подтехнологии, например `JS → Node.js/React.js/Vue.js`, `Python → Django/FastAPI`, `QA → QAA/QAM/QAMM`;
- `active` — доступность записи в каталоге.

В UI каталог отображается как раскрываемое дерево. Для каждой технологии доступны добавление дочерней записи, редактирование и удаление; новая запись также может создаваться на верхнем уровне.

Backend не разрешает циклическую вложенность и удаление технологии, пока у неё есть дочерние технологии, привязанные компетенции или она используется в профиле специалиста.

Текущий стартовый каталог: 1C, Android, Business analyst, C#, Design, DevOps, Flutter, GO, JS (Node.js, React.js, Vue.js), Java (Spring), ML (Computer vision, NLP), PHP (Laravel, Symfony), Product owner, Project manager, Python (Django, FastAPI), QA (QAA, QAM, QAMM), System analyst, iOS.

## Пока не входит

- история развития;
- assessments workflow;
- обучающие программы;
- performance review;
- полноценное управление каталогом компетенций (CRUD технологий уже реализован).


Миграция `2026_10_09_000001_complete_technology_tree.php` дополняет публичный каталог до 32 записей, включая Design → UX/UI, и синхронизирует родительские связи. Существующие IDs, active, alias/category и привязки специалистов сохраняются; создаются только отсутствующие имена. Название 1C используется в латинице; legacy 1С нормализуется при переносе позиций. Clients получает дерево через GET /api/specialists/catalog, не из своей копии каталога.
