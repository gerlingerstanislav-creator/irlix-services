# Skill development validation results

These are **independent simulated exercises**, not deployments or audits of user projects. They test the decisions, boundary cases and pure JS behavioral models generated by following the Skill. They do **not** test Vue components in a real browser.

1. [Dense records table + forms + filters](cases/01-enterprise-table.md): stale response ordering, draft protection, query persistence; Vue architecture/testing strategy assessed.
2. [API + OIDC/Keycloak](cases/02-api-auth.md): correct separation of backend authority, single-flight renewal, failure mapping; provider integration not simulated.
3. [Reactivity + performance/visual issue](cases/03-reactivity-perf-visual.md): stable row identity and memoized selectors with 12k records; no claim of speed or visual fix.

## Initial findings and improvements made

- Risk: "AbortController handles races" is insufficient. Added generation ID guard and test for old request rejection leaving new loading untouched.
- Risk: shared remote state overwrite while a user edits. Added separate draft ownership and test for refetch between edits.
- Risk: retry every 401 separately can cause request storms. Added single-flight session renewal, 403 differentiation and no infinite retry test.
- Risk: table index keys break identity after sort. Added stable-ID selection test with 12,000 synthetic rows.
- Risk: overclaim of visual/performance validation. Added an explicit evidence taxonomy and "not visually verified" requirement; performance now requires baseline and after measurement.
- Risk: changing frontend architecture without discovery. Added mandatory dependency/DS inventory and optional read-only audit helper.

## Environment limitations

Node built-in test runner and Python stdlib unit tests are executable without package downloads. No Vue/Vitest/Playwright dependencies or real application/browser environment are bundled; therefore no honest claim of passing mounted Vue tests, E2E, OAuth integration, screenshots or speed benchmarks can be made. A final integration test must be run against the consumer project's existing scripts and supported browsers.
