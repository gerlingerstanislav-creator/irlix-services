# Migration UI — пульт переноса

## Основная страница

Единственный интерфейс переноса открывается сразу по `/migration/`. В левом меню остаётся «Пульт переноса»; прежняя страница «Текущий интерфейс», её разметка, стили, polling и вкладочные скрипты полностью удалены. Старые ссылки `/migration/console` и `/migration/console/` после обработки OIDC автоматически заменяются на `/migration/` с сохранением query-параметров и hash, включая выбранный сервис.

Frontend находится в `apps/migration`, собственный image/container `migration-web`. Portal не содержит экранов или polling мигратора. Оболочка и компоненты — общие `UiAppShell` и `@irlix/ui`; Dashboard выбирается через общий launcher. Доступ проверяется через authenticated Employees access API и общую функцию `isPlatformAdminAccess`; ошибка проверки не открывает интерфейс.

`src/main.js` отвечает только за авторизацию и запуск `MigrationConsole.vue`; состояние и композиция пульта находятся в `MigrationConsole.vue`, `migration-console-model.js` и `migration-console.css`. Polling сохраняет черновики, DOM, фокус и положение курсора. Настройка подключения и её уведомления показываются в отдельном окне; архивы и действия с ними — в окне «Бэкапы». Исторические снимки Employees/Vacations остаются доступны через существующие API.

## Компактная компоновка пульта

Выбранный сервис указан в breadcrumbs. Блок этапов уплотнён: текст слева, действия справа. Верхние заголовки таблицы и журнала образуют общую строку одинаковой высоты; заголовки колонок обеих таблиц также выровнены и имеют высоту 30 px; пояснение таблицы находится справа от заголовка и целиком доступно в tooltip. По умолчанию таблица и журнал занимают равные половины. Вертикальный разделитель — линия шириной 1 px без отступов и обводки при наведении; невидимая зона захвата сохраняет удобство перетаскивания. Он изменяет их ширину мышью или стрелками клавиатуры (20–80%); Home/End выбирают границы, двойной щелчок возвращает 50/50. Polling не сбрасывает размер панелей. На mobile блоки располагаются последовательно, разделитель скрыт. Строки таблицы уплотнены без изменения шрифтов; счётчики объединены в одну колонку «Успешно / Ошибки / Предупр.» с тремя значениями через `/`. Ошибки и предупреждения остаются кликабельными фильтрами журнала. Все колонки таблицы переноса, кроме первой, выровнены по горизонтальному центру, включая заголовки и состояния; фильтры журнала — компактные UiButton с aria-pressed, checkbox автопрокрутки выровнен по центру. Список сервисов не имеет обводок и закруглений; «Все сервисы» отделён дополнительным интервалом, надпись «Очередь переноса» удалена. У каждого пункта справа сверху шестерёнка настроек БД, под ней иконка дискеты «Бэкапы». Наведение и фокус выделяют только кнопку иконки; весь пункт подсвечивается при наведении на выбор сервиса. Для «Все сервисы» шестерёнка открывает выбор подключения; действия нереализованных модулей disabled. Сводка доступов в блоке этапов «Все сервисы» и надпись «Обновлено» с датой удалены во всех сервисах. Уведомления проверки/изменения подключения остаются только в UiDrawer настройки БД; polling сохраняет значения, DOM, focus и caret.

«Бэкапы» открывает UiDrawer выбранного сервиса, независимо от текущего выбора таблицы. В одном списке показаны снимки пульта и исторические снимки Employees/Vacations с источником, датой, ID и отметкой восстановления. Общие снимки находятся в «Все сервисы». Удаление требует отдельного подтверждения и физически удаляет архив на сервере. Возврат требует точной фразы RESTORE <SCOPE> и использует существующий API соответствующего типа снимка; уже восстановленные снимки нельзя восстановить повторно. Глобальная активная операция переноса или snapshot/restore блокирует действия. Ошибки списка, удаления и возврата показываются только в соответствующем окне бэкапов. Новый DELETE /api/migration/console/snapshots/{scope}/{snapshot} требует platform-admin, allowlisted scope и numeric ID; ops сериализует его общим LOCK, проверяет активный legacy snapshot и удерживает SQLite BEGIN IMMEDIATE и файловый lock checkpoint-скрипта до конца удаления. Не удаляются архивы другого сервиса, история операций или metadata. Для старых снимков используются прежние endpoints /snapshots и /vacations/snapshots. GET console/state также возвращает snapshot_operation для блокировки и отображения операций исторического snapshot API.


## Создание точки из окна бэкапов

В UiDrawer «Бэкапы» каждого реализованного сервиса и «Все сервисы» есть UiButton «Создать точку отката». POST /api/migration/console/snapshot принимает scope окна, не активной таблицы. Он требует platform-admin и отсутствие активных операций; legacy credentials/verification не требуются, импорт не запускается. Окно остаётся открытым; polling добавляет проверенную точку, показывает готовность/ошибку и сохраняет фокус/draft. Кнопка заблокирована на время задачи, загрузки списка и потери связи.

Clients/Timesheets имеют собственные подключения и snapshots; «Все сервисы» охватывает Employees, Vacations, Clients и Timesheets. На время consistent checkpoint останавливаются writers выбранной схемы (включая Employees events и Vacations calendar-sync), Migration API/worker. Старые глобальные checkpoints из двух схем видны и доступны для удаления, но восстановление через новый глобальный контур запрещено: требуется новая точка из четырёх схем. API/server проверяют состав manifest независимо от disabled в UI. Снимки отдельных старых Employees/Vacations продолжают использовать собственные legacy endpoints.

Во время создания точки отката API временно останавливается для согласованности снимка. Окно бэкапов и подтверждение переноса заранее объясняют ожидаемые 502/503. При подтверждённой активной операции snapshot (включая первый checkpoint очереди переноса) такие ответы показываются нейтральным статусом ожидаемой паузы, повторная проверка связи продолжается, действия остаются заблокированными. Окончательный результат не объявляется до успешного ответа API. Ошибки иных типов/вне создания снимка остаются обычными ошибками; поля форм и настройки интерфейса не сбрасываются.

### Сотрудник и периоды в журнале

Для конфликтов Employees/employment журнал показывает ФИО и логин из сохранённого контекста и кнопку «Сотрудник и периоды». Общий `UiDrawer` показывает ID сотрудника в обеих БД и таблицу исходного периода / незакрытых целевых периодов с типом сотрудничества и датами. Снимок новых ошибок помечен как сохранённый при возникновении ошибки; для старых ошибок используются текущие read-only данные, которые могли измениться после запуска. Ошибки чтения остаются в этом окне. Просмотр не повторяет импорт и не исправляет конфликт; фоновые опросы не обновляют открытые подробности.
