# Migration UI — единый контроль переноса

## Основная страница

Единственная рабочая страница Migration в System: `/system/migration/control/`. Прежний путь `/system/migration/` автоматически переводится сюда, сохраняя query и hash. Standalone: `/migration/control/`, старые `/migration/`, `/migration/console/` и `?view=control` нормализуются после OIDC. Старый frontend «Пульт переноса» удалён: он больше не отображается как отдельный маршрут, пункт меню, вкладка или ссылка. Backend API, orchestration, mappings и исторические snapshots остаются доступными и не удаляются.

## Таблица и действия

`MigrationControl.vue` показывает корень операции, строки сервисов и разворачиваемые сущности; вверху компактная строка с выбором истории, запуском, остановкой, снимками, прелоадером и скачиванием отчёта. Для каждого сервиса непосредственно в строке таблицы есть кнопка с общей иконкой настроек (aria-label `Настройки подключения: <сервис>`), открывающая `MigrationAdministration.vue` **с уже выбранным сервисом**, без второго общего селектора. При отсутствии текущей операции начальная таблица содержит все четыре сервиса и кнопки настроек напротив каждого.

Настройка изолирована в drawer, использует проверенный backend `/api/migration/state`, `/services/{service}/connection`, `/verify` и `/reachability`. Поддерживаются host, port, database, user, password (пустое значение не меняет хранимый), SSL, read-only acknowledgement, а для Clients также Legacy APP_KEY, алгоритм и явное удаление ключа. Секреты ни при открытии, ни в отчёте не показываются. При активных операциях изменение настроек заблокировано UI и backend. После успешного изменения повторно загружается только публичное состояние подключения, остальные формы не сбрасываются.

Кнопка «Снимки» находится в верхней строке и открывает отдельный drawer с текущими и историческими снимками, фильтром scope и действиями создать/удалить/восстановить. Все действия требуют авторизации platform-admin и серверных блокировок; restore подтверждается фразой `RESTORE <SCOPE>`. Нажатие «Снимки» само по себе ничего не записывает, восстановление и повторный перенос не запускаются автоматически.

## Наблюдаемость

Во время запроса прелоадер находится в стабильном слоте заголовка и не сдвигает таблицу. Ошибки связи и отчётов отображаются вне потока, статус читается независимо от тяжёлого JSON. Запрос остановки доступен по последнему известному активному operation ID даже при кратковременном сбое GET, но ожидание завершения текущего этапа и серверная проверка остаются обязательными. Исторические доказательства не подменяются новым run ID и не изменяются редактированием фильтров.

## Проверки

- `node --test apps/migration/tests/*.test.mjs` — модель и контракт единой страницы.
- `npm --prefix apps/migration run build` и `npm --prefix apps/system run build` — сборка standalone и System.
- `apps/migration/tests/migration-control.browser.cjs` — синтетический browser flow в standalone и в System, включая шестерёнку настроек, параметры подключения, снимки, redirect старых URL, скачивание evidence, offline/cancel и мобильную таблицу.

Полная модель состояния, классификации строк, истории и доказательного отчёта: [MIGRATION_CONTROL.md](MIGRATION_CONTROL.md).
