# Передача незавершённых задач между чатами

Только для длительных/незавершённых задач, когда есть риск потерять точное состояние. Не создавать handoff для каждой мелкой правки.

Файл `<issue-or-slug>.md` — максимум краткая оперативная сводка:
- Цель и границы, ссылки на утверждённые требования (без дублирования ТЗ).
- Точная feature-ветка, PR, SHA и проверенное состояние (с датой).
- Что реально сделано / что не сделано.
- Известные блокеры, воспроизводимые ошибки, доказательства проверок.
- Следующее действие; связанные ссылки на код/тесты.

На новом сеансе проверять SHA и актуальность статуса в Git: handoff — навигатор, не источник истины для текущей ветки, CI или production. Не хранить секреты/персональные данные; не переносить приватное ТЗ из `ideas` в публичный репозиторий. После закрытия обновить/архивировать handoff при необходимости.
