# Состояние платформы IRLIX Services

> Последняя редакция: 2026-10-09. Это обзор реализации, а не очередь задач и не подтверждение готовности production. Проверяйте актуальное состояние кода, CI и развёрнутого окружения перед выводами о готовности.

## Общая картина

Платформа ведётся в монорепозитории. Реализованы приложения и серверные компоненты для сотрудников, отпусков, клиентов, таймшитов, специалистов, подбора персонала и конвертации CV, а также Platform Core, портал и дизайн-система. Наличие компонента **не означает**, что все предусмотренные ТЗ сценарии завершены.

## Состояние по направлениям

| Направление | Подтверждённое состояние | Открытые вопросы / ограничения |
| --- | --- | --- |
| Платформа / Portal / Core | Есть приложение портала, Platform Core и единая UI-библиотека | Статус всех permission-сценариев и эксплуатационная готовность требуют отдельной сверки |
| Employees | Реализуются модель сотрудников и организационная структура | Покрытие всех сценариев ТЗ не сверено |
| Vacations | Есть frontend/backend сервиса | Миграция заявлений, согласований и файлов требует проверки |
| Clients | Есть frontend/backend, запросы, позиции и попытки | Корректность и полнота переноса legacy-данных требуют проверки |
| Timesheets | Реализован MVP ввода, подтверждений и управленческой матрицы | Требуется регрессионная проверка недавних изменений |
| Specialists | Есть frontend/backend | Полнота относительно ТЗ не проверена |
| Recruitment | Есть frontend/backend | Полнота относительно ТЗ не проверена |
| CV Converter | Есть pipeline PDF/DOCX → извлечение → canonical CV → DOCX/PDF | Legacy .doc, OCR и клиентские шаблоны не поддерживаются в описанной итерации |
| Migration | Есть отдельный frontend и операции миграции | Перенос данных находится в стадии доработки |
| CI/CD / инфраструктура | Есть CI/CD и окружение развёртывания | Текущие проверки и реальный статус production отслеживаются по CI, не по этому документу |

## Текущая итерация

Актуальный состав работ определяется задачами GitHub Issues и содержимым `development`; в этот файл переносится **только краткая сводка**, когда она подтверждена.

## Правила актуализации

- При изменении готовности функционального направления обновлять соответствующую строку.
- Не переносить сюда чек-листы задач: для них [BACKLOG.md](BACKLOG.md) и GitHub Issues.
- Не переносить сюда историю изменений: для неё [CHANGELOG.md](../CHANGELOG.md).
- Не отмечать статус «готово в production» без проверки выкладки.
- Продуктовые требования и решения фиксируются в `ideas/company-internal-services-*/`; подробности реализации — в документации и коде этого репозитория.
