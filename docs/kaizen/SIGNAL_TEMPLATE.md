# <Краткий наблюдаемый симптом / класс проблемы>

- **Scope / теги:** `<service>`, `<subsystem>` (совпадать с каталогом/контрактом проекта)
- **Fingerprint:** `<стабильное техническое или процессное описание симптома>`
- **Впервые замечено:** `YYYY-MM-DD` (по проверенному событию)
- **Последний эпизод:** `YYYY-MM-DD`
- **Состояние анализа:** `наблюдение` / `повторение` / `причина подтверждена` / `эффект не проверен` / `эффект проверен`

## Эпизоды и доказательства

- `YYYY-MM-DD` — что произошло, expected/actual или повторная стоимость; ссылка на Issue, PR, commit, CI или другой устойчивый артефакт; источник и ограничения доказательства.

## Анализ

- **Подтверждённые факты:** ...
- **Гипотеза (если есть):** ... (не выдавать за подтверждённую первопричину)
- **Подтверждённая причина (если установлена):** ...
- **Связанная принятая профилактика (если существует):** ссылка на Issue/PR; **не** вносить несогласованные идеи как работы.
- **Проверка эффекта:** `не проверено` / ссылка на проверку и результат / `не сработало`.

Не указывать количества эпизодов без проверяемого перечня независимых событий. Даты, ссылки, подтверждения, решения владельца и проверки не придумывать. Не хранить чувствительные данные.
