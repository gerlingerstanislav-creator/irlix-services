# Migration — диагностические сводки без данных для разрешения ошибок

**Класс наблюдения:** повторные частичные запуски Timesheets при наличии агрегированной ошибки и отсутствии доступной оператору предметной информации о source/target строках.

**Наблюдение (22–23.10.2026):** владелец неоднократно передал отчёты, в которых `SOURCE_ROW_UNRESOLVED` и `DEPENDENCY_BLOCKED` повторялись в Timesheets; архивный отчет сокращал показ построчных элементов до примеров, а отдельная форма `members` не позволяла исследовать даты конкретных `timesheets`. Частичный результат затем сменился остановкой в конфликтном Dry run (защита от записи сработала, но проблемные source даты не стали доступны для исправления). Публичное доказательство реализации ограниченной архивной выдачи — `apps/migration/src/MigrationControlTree.vue` и `services/migration/app/Migration/Core/ControlReport.php` до PR #560; конкретное содержание данных владельца не сохраняется в Git.

**Повтор:** как минимум два отдельных этапа расследования одной продолжающейся ошибки; частота не интерпретируется как независимые инциденты инфраструктуры.

**Причина по коду:** интерфейс выводил агрегированные причины и не имел on-demand пути чтения `source timesheets → source rates → source member → Employees → Clients project_members/member_terms` для конкретной записи. Текущая модель допускает только один Clients member на всю историю исходного member; требование `rates.from/to` полностью совпадать с одним member_terms не универсально для разрезанных периодов. Статус фактических source данных до пользовательской сверки не установлен.

**Мера:** PR [#560](https://github.com/gerlingerstanislav-creator/irlix-services/pull/560) — защищённый администраторский курсорный журнал ошибок и post-failure read-only карточка каждой Timesheets/rates/members ошибки; не заявлять что изменение UI само исправляет миграцию. QA должен отдельно проверять факт доступности **всех** ошибок и точность их ID/даты/связей, а не только агрегированный счетчик.

**Проверка эффекта:** при следующем реальном переносе оператор должен суметь выяснить без SSH и raw JSON причину любой блокирующей записи; до этого результат **не подтверждён**. Конечная успешность реальной миграции требует отдельной сверки.
