# AI-команда Irlix Services — ChatGPT Plus / Codex / GitHub

## Что работает без отдельного OpenAI API

Для проекта используем уже подключённый GitHub и Codex, авторизованный через **учётную запись ChatGPT** (при наличии доступа к Codex Cloud в рамках подписки и её лимитов). Отдельный OPENAI_API_KEY, оплата Responses API и IDEAS_READ_TOKEN **не требуются**.

1. Владелец общается с PM в ChatGPT. PM определяет сервисы задачи и контекст через AGENTS.md и docs/CONTEXT_SCOPE.md.
2. Роли Analyst, Designer, QA, Developer:<service>, PlatformEngineer и ProductAdvisor описаны в .github/agents/*.agent.md. Это **инструкции для отдельных заданий и Codex-сессий**, а не параллельно запущенные постоянно AI-процессы.
3. Изменения делают через рабочую ветку, созданную от свежей development, и PR только в development.
4. Workflow .github/workflows/ai-team.yml **без модели** автоматически определяет сервисных владельцев и необходимые роли по списку изменённых файлов и публикует один обновляемый комментарий в PR. Он не анализирует бизнес-требования, не пишет код, не тратит AI-токены и не использует API.
5. GitHub Actions выполняет автоматические Node/PHP/Chromium проверки, блокируя CI verified при ошибках.
6. После подключения репозитория в Codex можно запускать нативный **Codex Code Review** для PR, в том числе автоматический, если он доступен и разрешён в настройках. Review — это дополнительный анализ, **не** прохождение QA, а замечания исправляются отдельным Codex/ChatGPT-заданием.

## Что нужно сделать владельцу в Codex

1. Открыть https://chatgpt.com/codex и войти **через тот же ChatGPT-аккаунт**, что используется для подписки. Для Plus действует лимит использования; доступность Codex Cloud зависит от аккаунта и настроек.
2. Подключить GitHub и предоставить Codex доступ к **irlix-services**, не ко всем репозиториям. Не выдавать production credentials. Выбор репозитория — пользовательское действие; GitHub-коннектор самого чата и GitHub App для Codex могут требовать разные разрешения.
3. В https://chatgpt.com/codex/settings/code-review найти irlix-services и включить Code Review / Automatic review, **если доступно**. Для проверки можно написать комментарий `@codex review` в обычном PR.
4. В задачах Codex указывать **начальную ветку development**, не main, и профиль роли: например «Используй .github/agents/Developer.agent.md для Clients, выполни задачу только в Clients; инструкции AGENTS.md обязательны».
5. Если нет возможности включить облачный review, оставляем ручные Codex-сессии по подписке и GitHub Actions тесты. Не притворяемся, что фоновые AI-проверки работают.

Никаких OPENAI_API_KEY или переменной AI_TEAM_ENABLED настраивать не нужно. Если они уже заведены для старого прототипа, рекомендуется удалить их в GitHub Settings → Secrets and variables → Actions **после проверки, что их не использует другой workflow**. Новый AI Team routing работает без них.

## Конкретный цикл разработки

- **PM / основной чат:** постановка задачи, выбор сервисов, принятие решения по спорным требованиям, передача замечаний, контроль QA и финальных SHA.
- **Analyst:** бизнес-правила и документация в приватном ideas по согласованному ТЗ. Без доступа к приватному ideas бизнес-приёмка — NEEDS_INFO, не PASS.
- **Designer:** UX, использование packages/ui, необходимость общих компонентов; визуальное заключение только при фактическом просмотре интерфейса, а не на основании одного diff.
- **Developer:<service>:** full-stack в границах одного сервиса, отдельная ветка, реализация и тесты.
- **PlatformEngineer:** shared/auth/permissions, инфраструктура и межсервисные контракты, только когда затронуты.
- **QA:** независимые проверки из CI и при отдельном запросе исследовательская проверка в Codex или ChatGPT.
- **ProductAdvisor:** предлагает идеи по запросу владельца, без автоматического старта разработки.
- **Codex review:** нативный рецензент PR при подключённом аккаунте, его вывод нельзя объявлять полноценным QA.

Ошибка в CI автоматически делает PR «к исправлению» по результатам GitHub Actions. **Непрерывного автоматического цикла «QA нашёл → самостоятельный AI-разработчик исправил → QA повторно проверил» в Plus-only конфигурации нет**: PM или владелец должен инициировать новую Codex-задачу/исправление. Если пользователь занимается следующей задачей, GitHub CI работает независимо от основного чата, но не отправляет ему событий напрямую. PM обязан читать фактический результат GitHub перед утверждением готовности.

## Безопасность и ограничения

irlix-services — публичный, ideas — приватный. Бизнес-данные, закрытая документация, персональные данные и секреты **никогда** не помещаются в публичные PR, комментарии и репозиторий. Текущий no-API workflow не читает ideas и не отправляет документы третьим сторонам. Нативный Codex Code Review работает в контуре выбранного GitHub-интегрированного репозитория; подключение закрытого ideas и доступы к нему требуют отдельного решения владельца.

Отдельного TEST-стенда сейчас нет. Playwright работает в локальном frontend preview со синтетическими API; реальные backend/permission интеграции не считаются покрытыми. Никаких автоматических merge или production deploy по результатам AI, Codex или role routing: релиз строго по прямой команде владельца через текущий процесс development→main.

## Технические файлы

- .github/agents/*.agent.md — политики специализированных исполнителей;
- AGENTS.md — общие правила Codex и code review;
- scripts/agents/route.mjs — маршрутизация по путям;
- scripts/agents/handoff.mjs — детерминированное PR handoff-сообщение, без API;
- .github/workflows/ai-team.yml — запускает handoff по PR;
- scripts/qa/tests/agent-route.test.mjs и no-api-team.test.mjs — инварианты безопасности и маршрутизации;
- docs/QA.md — что реально тестируется автоматически.

## Результаты / границы внедрения

**Автоматизировано:** маршрутизация PR по владельцам, существующие CI/QA checks, фиксация результатов и связь с SHA.

**Доступно после подключения Codex:** облачные задачи разработки и AI Code Review в пределах возможностей подписки, с отдельным запуском или включённым auto-review.

**Не реализовано без внешнего AI-runtime:** полностью самостоятельное взаимодействие всех AI-ролей, автоматическое кодовое исправление и непосредственные уведомления в этот чат. Эти ограничения не заменять обещаниями «фона».
