# Маршрутизатор контекста IRLIX Services

Цель: минимизировать чтение, **не ослабляя действующие правила**. Это навигационный документ, а не замена `AGENTS.md`, `docs/CONTEXT_SCOPE.md`, регламентов или продуктовых ТЗ. Все обязательные проверки и запреты сохраняются.

## Алгоритм (перед первым чтением большого документа)

1. Классифицировать запрос: ответ/анализ без изменений, docs/copy, локальный UI, локальный backend, данные/миграция, межсервисная интеграция, auth/security, CI/deploy, системная задача.
2. Зафиксировать **один первичный сервис/модуль и конкретный сценарий**. Для неясного пути искать имя файла, символ, маршрут, endpoint. Поиск путей и совпадений не требует загрузки содержимого найденных файлов.
3. Читать `AGENTS.md` и минимальные правила `docs/CONTEXT_SCOPE.md`, затем лишь релевантные разделы политик и документов из таблицы ниже.
4. Читать целевые фрагменты реализации, требования и тесты. Не загружать весь основной сервис: даже его полный ТЗ — только когда узкие разделы не позволяют понять инвариант.
5. При фактической зависимости читать **только контракт** второго сервиса. Не переходить автоматически к зависимостям второго сервиса.
6. Расширять scope лишь при конкретной причине: затронутый контракт, обнаруженная ошибка, требование/инвариант, тест или риск; фиксировать эту причину в рабочем плане.
7. Не восстанавливать историю всех чатов, всего проекта, всех Kaizen-сигналов или всех Issue. Искать точечно по текущему классу проблемы.
8. При записи изменений документации обновлять только существующий источник истины; индексы и handoff — исключительно ссылки и короткие ориентиры.

## Уровни чтения

- **L0 / маршрутизация:** обязательные короткие глобальные правила и тип задачи. Не означает чтения всех документов, на которые есть ссылки.
- **L1 / локальный:** нужные функции, компоненты, тесты и точные разделы ТЗ одного сервиса.
- **L2 / контракты:** конкретный DTO, API, event, schema, permission/scope или общее UI/API; только при доказанной связи.
- **L3 / системный:** полный системный анализ лишь при сквозном аудите, платформенном изменении или прямом запросе на комплексное изучение.

## Режимы работы (не меняют требований Git/CI/QA)

| Режим | Применимость | Анализ и проверка |
|---|---|---|
| Fast | Copy, стили и локальный UI без контрактов | Локальные ограничения, реализация, целевая проверка; дополнительные роли и полные ТЗ не подключать |
| Standard | Изменение локальной логики, endpoint или сценария | Анализ нужных инвариантов → реализация → целевые unit/integration проверки и QA по риску |
| Deep | БД, миграция, auth, security, межсервисная схема, архитектура | Полный набор **релевантных** ролей и проверок; соседние сервисы — сначала контракты |

Режим выбирается по реальному влиянию изменения, а не по длине просьбы. Fast не отменяет permissions, защиту данных, Git/CI, тестовые доказательства, QA и требования к итоговому отчёту. При обнаружении большего риска перейти в Standard/Deep.

## Что читать по триггеру

| Событие | Документы (только нужные разделы) |
|---|---|
| Любая реализация | `AGENTS.md`, `docs/CONTEXT_SCOPE.md`, целевые фрагменты `docs/policies/ENGINEERING.md` |
| Ветки, push, PR, CI, релиз | `docs/BRANCHING.md`, `docs/policies/GIT_RELEASE.md`, `docs/CI.md`, `docs/REPORTING.md` по выполняемой операции |
| UI | сервисный UI, применяемый компонент `packages/ui`; дизайн-политика только по необходимости |
| БД/миграция | целевые модели, ограничивающие инварианты, соответствующее ТЗ и миграционный контракт |
| Auth/security | `packages/auth`, конкретные permission/scope и соответствующие security-политики |
| Issue/бэклог | `docs/policies/ISSUES.md` |
| Work и передача ролей | `docs/AGENT_CONTEXT_PROTOCOL.md`, `docs/AI_TEAM.md` и `docs/policies/TEAM_RULES.md` только необходимые секции |
| Kaizen-сигнал | поиск в `docs/kaizen/` по классу дефекта; полный регламент — при оформлении улучшения |
| Развёртывание | `docs/DEPLOYMENT.md` и релизный регламент |
| Продуктовое правило | релевантная часть `ideas/company-internal-services-81-2.4/services/<service>/` |

**Временное действующее решение:** кастомные Skills не назначаются, не читаются и не применяются до отмены этого режима; ролевой workflow остаётся действующим (`docs/policies/TEAM_RULES.md`).

## Проверка экономии контекста

Для сравнения брать три задачи: 1) ширина ячейки Timesheets, 2) локальное API-изменение Clients, 3) цепочка Clients → Timesheets → Migration. Отмечать ориентировочное количество прочитанных файлов/разделов, расширения scope и пропущенные инварианты. Не назначать формальные токен-бюджеты, если они вредят корректности.

Карты конкретных сервисов: [context/README.md](context/README.md). Незавершённые задачи: [tasks/README.md](tasks/README.md).
