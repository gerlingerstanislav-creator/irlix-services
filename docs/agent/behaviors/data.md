# data — хранение, история и перенос

**Условия:** схема/ORM/SQL, связи и ограничения, импорт, массовая обработка или изменение исторических данных.

**Источники:** затронутые модели/миграции/запросы, утверждённые инварианты и периоды, реальные доступные сведения об объёмах, прямые потребители, [DATABASE](../../horizontal/DATABASE.md). Не предполагать пустую БД или воспроизводимость данных.

**Действия:**
1. Определить владельца данных, гранулярность факта, ключи/уникальность, жизненный цикл, историю, удаления, подтверждения и блокировки. Проверить, какую информацию можно потерять.
2. Проверить достаточную нормализацию и целостность. Не дробить сущности или индексы без инварианта/запроса; NO CHANGE допустим. Сравнить существенные варианты по реальным последствиям.
3. До изменения работающего сервиса оценить совместимость старой/новой версии, блокировки и ресурсы, последовательность миграции и способ восстановления. Проверить необходимость сохранения старых ключей/данных, не решать её молча.
4. Для импорта/массовых изменений определить границы порций/транзакций по фактическому риску, идемпотентность, возобновление, прогресс, диагностику и сверку. Не считать отсутствие исключения доказательством полноты.
5. Проверить положительные/отрицательные случаи, границы периодов, повторный запуск, частичный отказ и сохранение истории там, где применимо.

**Результат/evidence:** модель с инвариантами, утверждённый план изменения/миграции, результаты сверки числа/связности/сумм по смыслу задачи, проверка восстановления или явно обозначенное ограничение. Не публиковать реальные записи/дампы в Git.

**Границы:** существенное изменение модели/миграции и принятие потерь согласовать до выполнения по workflow. Подтверждение воспроизводимости данных не означает права произвольно удалять их вне согласованного объёма. Изменение общих контрактов → integration; permissions/секретов → security. Не экспериментировать на production без конкретных полномочий.
