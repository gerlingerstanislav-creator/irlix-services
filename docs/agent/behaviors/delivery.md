# delivery — интеграция и разрешённый выпуск

**Условия:** изменение Git, PR, ожидание CI или production-релиз. Для read-only анализа этот модуль не создаёт обязанности коммитить отчёт.

**Источники:** свежие refs/PR, точный diff, checks и разрешения; [BRANCHING](../../BRANCHING.md), [GIT_RELEASE](../../policies/GIT_RELEASE.md), по событию CI/DEPLOYMENT и [операции GitHub](../../GITHUB_ACCESS.md).

**Действия:** создать отдельную рабочую ветку от свежей development. Сохранить параллельную работу; перед интеграцией получить свежую базу, разрешить конфликты в рабочей ветке и проверить результат. Завершённый объём интегрировать PR в development; дождаться относящихся обязательных checks точного итогового SHA, включая CI verified и Development release candidate. Draft PR может хранить незавершённую работу, но не разрешает её merge.

Production выпускать только по прямой команде владельца накопительным проверенным fast-forward development → main по каноническому release-регламенту. Разрешение сохраняется при исправлениях внутри задачи; новые существенные риски/изменение scope вынести владельцу. Не задавать «сразу в прод?» для обычной реализации. Не обходить защиту и не отменять чужой production deploy.

**Результат/evidence:** PR, SHA, фактические результаты QA/checks; при релизе полный состав накопленных изменений и подтверждённые deploy/smoke. Push/merge не равен выкладке. Queue/in_progress требует наблюдения и продолжения; сбой — диагностики и исправления. При реальном внешнем блокере сохранить [состояние](../STATE.md).

**Границы:** release-команда не разрешает несогласованные разрушительные операции/переработку продукта. При изменении вершины повторно проверить новый состав по Git-регламенту. Не выдавать старый успешный run за проверку нового SHA; не публиковать приватные материалы в PR/логи.
