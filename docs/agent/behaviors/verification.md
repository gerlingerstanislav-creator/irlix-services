# verification — доказать результат

**Условия:** любое утверждение о корректности или завершении. Проверка пропорциональна последствиям; отдельный QA не является синонимом самой проверки.

**Источники:** исходная цель/критерии и согласованные решения, фактический diff/версия, среда и сырые результаты проверок. Самооценка автора не является evidence. Инструменты проекта — [QA.md](../../QA.md).

**Действия:**
1. До реализации определить наблюдаемые критерии и существенные негативные/граничные случаи. Для локальной однозначной правки достаточно краткого чеклиста; формальный тест-дизайн и отдельный агент не обязательны.
2. Проверить полноту согласованного объёма, отсутствие посторонних изменений, сохранение соседнего поведения и чувствительных данных. Выбрать минимально достаточные реальные проверки: сборка/синтаксис, unit/contract/integration, UI/browser, permissions, данные — по влиянию.
3. Для UI получить фактическое визуальное evidence; для auth проверить запрещённые действия/чужой scope; для data проверить целостность/историю и нужные сценарии отказа. Synthetic API не подтверждает real-API/Keycloak/DB E2E.
4. Для существенных архитектурных/data/auth/migration изменений провести независимый review по [DELEGATION](../DELEGATION.md), независимо от объёма diff. При обычной реализации отдельный проверяющий предпочтителен, когда доступен и добавляет контроль. Самопроверку обозначать честно.
5. FAIL → воспроизводимое замечание → исправление → повторная проверка нового состояния. После merge сверить итоговый diff и checks точного SHA; не терять чужие изменения.

**Результат/evidence:** критерий/проверка, версия, среда, команда/наблюдение, PASS/FAIL/NOT TESTED/N/A и ссылка/результат. N/A требует причины неприменимости; нельзя назначить его недоступной обязательной проверке. Дефект: expected/actual, воспроизведение, серьёзность P0–P3 и evidence. Проверить дубликаты перед отложенным Issue.

**Границы:** production не является тестовой БД; проверки с изменением данных проводить локально/в изолированном TEST с синтетикой. Разрешённый production smoke отделять от продуктовой приёмки. Обязательный контроль не пройден → результат неполон; ограничение не маскировать зелёным CI. Независимый проверяющий не меняет бизнес-код вместо исполнителя.
