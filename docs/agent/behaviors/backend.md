# backend — логика и контракты

**Условия:** доменные операции, API, валидация, обработка ошибок и фоновые задачи.

**Источники:** конкретный endpoint/job и его тесты, утверждённый сценарий, прямые DTO/events; [BACKEND](../../horizontal/BACKEND.md) и затронутые проектные ограничения.

**Действия:** проверить входы, выходы, состояния, ошибки, авторизацию и владение данными. Найти существующий способ реализации; сохранить совместимость контракта. Учесть повторный запрос/доставку, конкуренцию и отказ зависимости там, где они меняют результат. Не добавлять универсальные слои без доказанной потребности.

Для каждого backend-изменения выполнить короткую оценку auth/data/trust boundaries. При изменении хранения подключить data; при изменении полномочий или sensitive flow — security; для чужих потребителей — integration. Обращение к чужим таблицам запрещено, источник данных определяется владельцем сервиса.

**Результат/evidence:** проверка ожидаемого поведения, затронутых невалидных входов/отказов и permissions; конкретная версия/среда/команды. Проверка синтаксиса не подтверждает интеграцию с БД или API.

**Границы:** неизвестный бизнес-переход → analysis. Существенный новый подход/внешний контракт сначала согласовать; в рамках утверждённого решения технические детали выполнять самостоятельно.
