# analysis — разобраться и оценить решение

**Условия:** неопределённый результат, новые бизнес-сценарии, противоречия или существенный архитектурный/продуктовый выбор. Для однозначной локальной правки достаточно проверки цели; отдельная спецификация не обязательна.

**Источники:** запрос и согласования, относящиеся утверждённые требования, фактическая реализация/контракт, наблюдаемый дефект. Проектные знания искать по [CONTEXT_SCOPE](../../CONTEXT_SCOPE.md). Слова автора реализации и собственные прошлые ответы не являются доказательством.

**Действия:**
1. Отделить цель от предлагаемого способа. Выяснить критерий успеха, границы, роли, состояния/переходы и неизвестные, влияющие на решение.
2. Проверить предпосылки и возможное опровержение: почему предложение может не сработать, что требуется сохранить, какие прямые потребители затронуты.
3. Для существенного решения сравнить минимум два реалистичных варианта, включая сохранение подхода, если оно осмысленно. Оценить риски, стоимость, совместимость, исторические данные и проверяемость. Для мелкого обратимого выбора не создавать искусственную сравнительную матрицу.
4. Дать независимую позицию с основаниями: поддерживаю / с оговорками / не рекомендую / недостаточно данных. Возражать предметно, без автоматического согласия или спора ради спора. При новом факте объяснить изменение рекомендации.
5. Зафиксировать наблюдаемые критерии: позитивные и существенные отрицательные случаи, исключения, права, границы. Не выдумывать неизвестные бизнес-правила.

**Результат/evidence:** подтверждённые источники и факты отдельно от гипотез; критерии, инварианты, влияние, варианты и нерешённые вопросы. Спорное предложение помечать PROPOSED, не утверждённым решением. Существенное принятое решение фиксировать в относящейся документации/ADR без публикации приватного ТЗ.

**Границы:** существенные архитектурные/бизнес-решения согласовать до зависимой реализации по [workflow](../WORKFLOW.md). Если ранее решение уже принято, проверить его применимость и продолжать в его пределах. Независимые понятные части не останавливать. При data/security/integration влиянии подключить соответствующий модуль. Право предложить улучшение не разрешает его внедрение.
