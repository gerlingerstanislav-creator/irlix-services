# Переход к адаптивным инструкциям

Объём: правила поведения, профили, маршрутизация и проверки этих механизмов. Прикладной код и требования в ideas не перерабатывались. Согласованность новой системы с содержимым ideas требует отдельного этапа; ссылку на источник нельзя считать такой проверкой.

## Карта сохранённых обязанностей

| Прежний источник / обязанность | Каноническое место теперь |
|---|---|
| AGENTS: исполнение до результата, полномочия, приватность | AGENTS + WORKFLOW |
| AI_TEAM, TEAM_RULES: распределение работы, ответственность PM | DELEGATION; один ведущий, реальные результаты помощников |
| GOVERNANCE: критическое мышление, неоднозначности, альтернативы | analysis + WORKFLOW; проектное владение документацией остаётся в GOVERNANCE |
| DatabaseEngineer: история, гранулярность, ключи, разумная нормализация | data + действующая горизонталь DATABASE |
| SecurityEngineer: server permission/scope, границы, отрицательные случаи | security + действующая горизонталь SECURITY |
| Designer/Developer: shared UI, состояния, фактическая визуальная проверка | frontend + действующая горизонталь FRONTEND |
| Backend и интеграции: контракты, владение данными, совместимость | backend/integration + соответствующие горизонтали |
| QA: критерии, дефекты, доказательства, ограничения среды | verification + DELEGATION; команды остаются в QA |
| Git: свежая база, PR, чужие изменения, проверки SHA | BRANCHING + GIT_RELEASE; delivery ссылается на них |
| Production: явная команда, весь development, fast-forward, CI/deploy/smoke | GIT_RELEASE, без изменения pipeline или полномочий |
| Незавершённая работа, смена контекста | STATE; PR checkpoint, существующие Issues без второго backlog |
| Повторные ошибки и Kaizen | CONTINUOUS_IMPROVEMENT + сохранённый протокол kaizen |
| Итоговые статусы / накопленный состав выпуска | REPORTING |
| Отключение Skills, отсутствие обязательного timing | AGENT_SKILLS + DELEGATION; пакеты сохранены, не активированы |

## Сознательные изменения процесса

- Обязательная смена ролей и отдельный QA для каждой Work-реализации заменены соразмерными действиями. Простая обратимая задача — самопроверка; существенная архитектура, данные, миграции, права и чувствительные границы — независимый review. Отсутствие помощника не отменяет нужного контроля и не превращает самопроверку в независимую.
- Fast/Standard/Deep, L0–L3 и интерфейс Chat/Work больше не определяют workflow. Намерение, неопределённость, влияние, последствия, полномочия и проверяемость оцениваются независимо, выбор пересматривается по новым фактам.
- Фиксированные Luna/Sol/effort-профили заменены выбором реально доступного достаточного исполнителя и эскалацией конкретной подзадачи. Запрет автоматического Astra и максимального effort сохранён; выдумывать переключение нельзя.
- Девять профилей сохранены как тонкие адаптеры; ProductAdvisor по-прежнему не разрешает самовольные продуктовые инициативы. Компетенция не требует отдельного исполнителя.
- Устранены разрешение прямой записи в development и команды применять отключённые Skills. Канонические ограничения не дублируются вторым workflow.
- PR-router даёт только подсказки по путям, не назначает обязательных Analyst/QA. Неизвестный риск не считается низким; тестовый PASS не равен review. GitHub Actions не запускает AI.
- STATE добавляет явный способ продолжения и учёта прочитанного. Это не автоматическое измерение всех токенов и не обещание фоновой работы.

## Поддержка и проверка

Изменять правило в каноническом месте; адаптер содержит ссылку, не копию процесса. Новое поведение добавлять по критериям BEHAVIORS, а не ради новой роли. При изменении источника проверять входящие ссылки, маршрутизатор, регрессионные тесты и сценарии VALIDATION.

Структурные тесты подтверждают достижимость инструкций и детерминированную маршрутизацию. Качество выполнения моделью и расход контекста подтверждаются только реальными сопоставимыми задачами. Порядок пилота: [VALIDATION](VALIDATION.md). При регрессии сохранять evidence и исправлять конкретное правило; не возвращать старый набор ролей без выяснения причины.
