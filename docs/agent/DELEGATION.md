# Исполнители и независимая проверка

Поведение выбирается по [WORKFLOW](WORKFLOW.md), а не по названию интерфейса Chat/Work. Один ведущий отвечает за результат. Он может выполнить несколько компетенций сам; роли не являются обязательными этапами или доказательствами качества.

## Когда делегировать

- Независимый review существенного изменения архитектуры, модели данных, миграции, прав или чувствительной границы.
- Параллельное исследование независимых вопросов или реализация с раздельными областями записи и согласованным контрактом.
- Диагностика после повторного FAIL без продвижения, когда отдельный контекст/компетенция добавляет проверку гипотезы.

Для однозначной локальной обратимой задачи ведущий выполняет работу и проверки самостоятельно. Новый сложный UX может требовать Designer, но два пикселя сами по себе этого не требуют. Обычная реализация получает отдельный review при наличии полезного независимого контроля; отсутствие помощника не отменяет проверки результата.

## Возможности и ограничения

Проверять фактическую доступность инструментов, источников и нужной среды. При отсутствии subagents локальную/обычную задачу продолжать одним агентом без дополнительного разрешения на переключение интерфейса; честно обозначить самопроверку. Для существенного изменения независимый review обязателен: если его невозможно получить, продолжать доступное исследование/подготовку в изолированной ветке, но не объявлять приёмку и не интегрировать/выпускать непроверенный результат. Назвать конкретный оставшийся контроль; владелец может отдельно принять его ограничение. Не выдумывать отдельные контексты или проверки.

Файлы .github/agents — адаптеры компетенций. GitHub Actions/handoff выполняет детерминированные подсказки и тесты, не запускает AI и не отправляет события в чат без отдельной интеграции. Наличие профиля/названия модели/Skill не означает фактический запуск.

## Поручение и возврат

Поручение: цель/конечный результат, scope, версия источников, критерии, нужные входные артефакты, разрешённые read/write paths, запреты и формат evidence. Давать минимально достаточный контекст; не форкать весь чат по умолчанию. При недостающем контракте помощник запрашивает его, а не угадывает. Полномочия помощника не шире полномочий ведущего.

Независимый проверяющий получает исходные критерии, фактический diff/SHA и сырые артефакты. Авторская самооценка, оправдания и рабочие гипотезы не являются основанием корректности. Общий Git не гарантирует слепой review; если проверяющий уже знает выводы автора, не заявлять слепую проверку. Для QA нужен отдельный от автора контекст; проверка критериев/UX/контрактов при существенном риске также выигрывает от отдельного проверяющего.

Возврат: выполненная работа, scope/версия, PASS/FAIL/BLOCKED/NOT_TESTED/N/A по критериям, evidence, замечания/риски, изменённые пути и следующий шаг. Если назначалась модель, указать фактически подтверждённую конфигурацию либо unverified. Поручение не равно результату: ведущий отслеживает реальные статусы, ждёт зависимые ответы, проверяет выводы и повторно направляет исправления на review нового состояния.

Один писатель на пересекающийся набор файлов; разные контексты не обеспечивают изоляцию общего filesystem. Перед записью/merge сверять свежую базу и соседние изменения. QA не исправляет бизнес-реализацию вместо разработчика; тесты пишет только в согласованной области.

## Модели и Skills

Использовать доступную модель, достаточную для подзадачи, с учётом риска и результатов. Изменение модели/effort возможно только при реальной поддержке среды; запрос не доказывает применение. Повышать конкретную подзадачу при существенном риске или неудачном результате, не запускать лишние роли ради экономии на каждом исполнителе. Astra — только по прямому указанию владельца; максимальные effort не являются автоматическим default. При неподдерживаемом выборе честно сообщать ограничение, не симулировать переключение.

Кастомные Skills отключены по [единому статусу](../AGENT_SKILLS.md). Компетенции самодостаточны без них. Никаких обязательных START/STOP, оценок длительности или таблиц времени ролей.
