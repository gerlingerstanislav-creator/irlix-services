# Состояние задачи и возобновление

Цель — продолжить ту же работу после прерывания, не потерять решения и не создать дубликат. Это состояние исполнения, не второй backlog и не Kaizen-история.

## Где сохранять

- Для изменения репозитория — секция `Agent checkpoint` в описании текущего PR; draft PR допустим до завершения. Не создавать новый PR/Issue для каждого этапа.
- Для утверждённой длительной/отложенной работы — существующая связанная Issue со ссылкой на PR; критерии и решения не дублировать, использовать ссылки. Политика [Issues](../policies/ISSUES.md) остаётся обязательной.
- Пока PR ещё нет и работа должна пережить прерывание: при разрешённой записи создать draft PR после появления содержательного diff; при отсутствии diff/доступа или read-only scope передать владельцу компактный handoff и явно отметить, что общей записи в репозитории нет. Не создавать фиктивный commit и не нарушать запрет записи ради checkpoint.
- Приватные критерии и материалы сохранять только в разрешённом приватном источнике; публичный PR содержит безопасное описание и ссылки, не ТЗ, переписку, секреты или реальные payload.

Сохранять после существенного принятого решения/изменения состояния, перед передачей работы или ожидаемым прерыванием; не после каждого чтения/команды. Явная команда остановиться прекращает действия немедленно; не выполнять дополнительные записи вопреки ей.

## Минимальный checkpoint

```text
Task / цель и конечная точка:
Scope и ссылки на согласованные критерии:
Принятые решения / разрешённые действия / запреты:
Ветка, PR, source SHA, изменённые пути:
Состояние исполнения:
Подключённые компетенции и существенные причины:
Сделано / осталось:
Проверки: критерий, SHA/версия, среда, результат, evidence/run URL:
Блокер и условие продолжения (если есть):
Следующий конкретный шаг:
Помощники/области записи, если работа продолжается:
```

Поле не требует повторного копирования уже доступного описания PR: достаточно ссылки и изменения. Не записывать скрытые рассуждения; только решения, наблюдения и действия. Локальная временная запись не считается общедоступной межсессионной памятью.

## Значения состояния

`needs_decision` → `working` → `verifying` → `ready_to_integrate` → `integrated`; при разрешённом выпуске → `releasing` → `released`. `blocked` может возникнуть на любом этапе; исправление FAIL возвращает в working. `completed` означает достижение конечной точки запроса, а не универсально production. Read-only исследование может завершиться без Git-состояний. `stopped` означает остановку владельцем, не выполненную задачу.

Это словарь checkpoint, а не новые GitHub labels. Метки backlog имеют свой существующий смысл: stage:done = подтверждённый production, stage:tested = production QA. В development писать «разработка завершена, ожидает выпуска»; не переименовывать labels и не закрывать Issue как production-tested по одному merge.

## Как продолжать

1. Найти существующую задачу по запросу, PR/ветке/Issue; проверить свежие refs и связанную параллельную работу. Не восстанавливать историю всей платформы.
2. Сверить checkpoint с фактом: diff, SHA, состояние PR, CI/deploy и актуальные решения. Историческое разрешение действует в прежних границах, но старый PASS не подтверждает новый SHA.
3. Проверить, не устранён ли блокер и не выполнена ли работа другим агентом. Не дублировать реализацию и не перетирать чужое.
4. Возобновить следующий доступный шаг. При изменившихся требованиях/рисках переоценить компетенции по workflow; обсуждать только новое существенное решение.

## Наблюдаемость контекста

В сложной задаче/пилоте сохранять компактный список реально прочитанных файлов/разделов и причину расширения scope; использовать автоматические журналы среды, если они доступны. Для простой правки отдельный журнал чтений не обязателен.

Различать объём загруженных материалов, текущий контекст конкретного агента и суммарное потребление всех вызовов/помощников. Точные токены брать только из фактической telemetry среды. При её отсутствии допустимы символы/оценка токенизатором с пометкой «оценка» и охватом; это не полный runtime-контекст и не стоимость. Не восстанавливать выдуманные токены из списка файлов и не объявлять экономию без сопоставимых измерений. Сам этот регламент не устанавливает автоматический сборщик telemetry.
